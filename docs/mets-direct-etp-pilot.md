# P1: прямое подключение ЭТП МЭТС — безопасный пилот

Подтверждённая официальная площадка: https://meetings.m-ets.ru/

## Реализовано

- Прямое получение публичного каталога **квартир** МЭТС с сайта самой площадки, не через Т-Банкрот/BidExpert.
- Из каталога извлекаются ссылки `/номер_торгов-номер_лота`; ссылки на чужие хосты отбрасываются.
- По каждой ссылке доступен прямой `fetch_lot` с разбором `NormalizedLot`: `external_id=trade-lot`, номер процедуры, название, тип, начальная/текущая цена (только с ценовым ярлыком), статус только при доказанной формулировке, кадастровый номер, дата окончания приема заявок.
- Для публичного предложения `Окончание приема заявок на периоде` записывается отдельно и НЕ принимается за общий срок завершения торгов.
- Коннектор зарегистрирован как `m-ets.ru`, но обычная `search()` намеренно блокирована; в `default_source_specs()` он не добавлен.
- Только HTTPS МЭТС, отсутствие авторизации, редиректов и внешних ссылок; задержка минимум 0,5 секунды на запрос и предел 10 карточек за пробу.

**Главное:** публичная страница каталога/спецпредложений сама по себе не доказывает полноту всех текущих торгов. Поэтому `complete_source_inventory=false`, `safe_for_archival=false`, `written_to_database=false` при любом результате.

## Пробный запуск на вашем компьютере (PowerShell)

Получите код ветки PR через `git fetch origin feat/p1-mets-direct-etp-readonly-20261028` и запускайте в отдельном тестовом окружении, чтобы не смешать с работающим production.

```powershell
$env:PYTHONPATH = "src"
python scripts/probe_mets_etp.py --max-lots 5 --confirm-network-access --output mets-pilot.json
```

Результат — локальный JSON с идентификаторами, названиями и ценами. Не требуется аккаунт ЕФРСБ или ЭТП. Файл не изменяет БД, S3 и публичную карту. Если `failed > 0`, скрипт возвращает код 2, ошибки без персональных данных и HTML; при изменившемся сайте не объявляет успешно собранный каталог полным.

## Почему пока не включаем в производственную очередь

1. Проверить на реальном Home, что текущий HTML каталога и деталей содержит стабильные публичные ссылки и элементы. CI-тесты сейчас используют локальные снимки семантически тех же полей, но не гарантируют актуальность разметки.
2. Добавить доказанное полное листание каталога /search, все нужные категории (участки, квартиры, здания, доли), контроль полного числа лотов и повторяющихся страниц.
3. Проверить статус, цена, даты через карточку по процедуре и журнал обновлений. До этого не выводить неизвестный статус как `active` и не архивировать из неполной выдачи.
4. Сопоставить по уникальному `trade_number + lot_number` и кадастровому номеру, сохраняя повторные стадии продаж; измерить реальный прирост уникальных объектов относительно существующих 5 источников.
5. После подтверждения доступности и тестирования на отдельной базе — controlled ingestion без архивирования; только затем согласованный rollout.

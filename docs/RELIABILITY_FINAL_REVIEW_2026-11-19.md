## Что уже реализовал предыдущий агент

В main есть агрегированный API, canonical source projection, русский интерфейс,
разделение текущего и исторического GEO, current-scope quality, экспорт JSON,
read-only whitelist, кеш манифеста и production acceptance workflow.
Последний production run `44451987592` завершился ошибкой навигации на публичный
сайт до загрузки экрана. Это не успешная приёмка последнего SHA.

## Найденные и исправленные пробелы

- Холодный/просроченный кеш выполнял полный operational/map обход внутри HTTP
  запроса. Прогретый p95 не проверял этот случай. Production-сверка вынесена
  в один фоновый поток с отдельной read-only repeatable-read транзакцией.
  Pending/stale/error показаны явно; до результата зелёного статуса нет.
  Обновление общего snapshot также выполняется в фоне: после начальной загрузки
  истечение TTL не блокирует запрос на пересчёте счётчиков. Старый generated_at
  сохраняется и сопровождается refresh_state. p95 проверяется также по полной
  измеренной серии, включая первый запрос, а не только по прогретой части.
- Новый dataset мог наследовать сверку предыдущего на срок кеша. Ключ теперь
  включает ID, версию, размеры, статус и время публикации. Старое положительное
  доказательство не подтверждает новый набор.
- Подтверждённый сбой манифеста занижал общий статус до degraded. Теперь это
  incident; ожидание проверки остаётся degraded. Причины incident идут первыми.
- Подпись «Сверены версия и размеры» появлялась даже при неуспешном манифесте.
  Теперь ошибка и ожидание имеют отдельные понятные подписи.
- Отчёты тяжёлой сверки получили checked_at; текущая полнота считается одним
  SQL-агрегатом. Интерактивный snapshot использует repeatable read/read only.
- Медленный предыдущий refresh мог перезаписать более новый. Добавлен номер
  запроса; устаревшие ответы игнорируются, успешные данные сохраняются при сбое.
- Интерфейс разделён на девять именованных компонентов. Технические ошибки
  доступны в раскрытой строке; основные сообщения написаны по-русски.
- Общий CSS перебивал desktop-навигацию и превращал подпись «Избранное» в badge.
  Исправлена специфичность; desktop меню 188 px, мобильное — 56 px.
- Расширено скрытие Bearer/Basic, Cookie, URL credentials и quoted secrets.
- Configured denominator сохранён. Дополнительно указаны effective_scheduled,
  pilot и возраст полного снимка; scheduled сохраняет совместимое значение.

## Проверки и границы готовности

Добавлены regression cases для manifest failure/pending, смены dataset,
неблокирующей холодной сверки, read-only PostgreSQL snapshot, stale refresh,
порядка источников, неизвестного enum, JSON download и гонки ответов.
Локальная визуальная проверка использует read-only снимок production-метрик,
подставленный в локальный WEB. Это проверка вёрстки, не live production-приёмка.

Перед закрытием необходимы зелёный полный CI, exact-SHA deployment и повторная
live приёмка desktop/tablet/mobile и производительности. Результаты записываются
после фактического выполнения. Работы по восстановлению Source/Processed/GEO
из общего плана выполняются отдельными операторскими кампаниями; API раздела
«Надёжность» не меняет Lot, Source, Canonical, оценки или audit history.

## Безопасность диагностической приёмки

Playwright при сетевой ошибке API включил Cookie в сообщение исключения прогона
44469389994. Сессии admin с token_version 37 отозваны изменением версии на 38;
это также завершает другие входы admin с этой версией и требует повторного входа.
Содержащие cookie журналы и два артефакта этого прогона удалены из GitHub;
локальные диагностические тексты отредактированы. Ошибка самого прогона остаётся
зафиксированной, успешной приёмкой он не считается. Пароль в вывод не попадал.

В тестах добавлены маскирование сессионных cookies в Actions и безопасные ошибки
authenticated GET без исходных заголовков. JSON метрики и неполные серии теперь
пишутся в отдельные файлы: body-only attachment терялся при line reporter.
Проверка p95 использует отдельную API-сессию и сверяет SHA API с deployment.json;
реальный браузерный вход остаётся обязательным в проверке данных и вёрстки.

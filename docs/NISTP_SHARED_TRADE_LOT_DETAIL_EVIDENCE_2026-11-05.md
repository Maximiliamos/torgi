# NISTP — общий URL торгов и индивидуальные лоты, 05.11.2026

## Подтверждено пользователем в браузере

Публичная карточка `https://nistp.ru/bankrot/trade_view.php?trade_nid=502957` открывается **одинаково** по ссылкам каталога «Лот № 4» и «Лот № 5».

- Код процедуры: `72113-ОАОФ`.
- В документе явно показаны **10 отдельных секций**, от «Лот № 1» до «Лот № 10», каждая с индивидуальными полями «Номер лота», «Наименование имущества», «Cведения об имуществе», «Начальная цена», «Размер задатка» и «Статус торгов».
- Лот 4: `nistp.ru:502957:4`, цена **3 274 000.00 ₽**, задаток **327 400.00 ₽**, кадастровый номер `77:01:0004002:6614`, площадь 14.3 м².
- Лот 5: `nistp.ru:502957:5`, цена **3 274 000.00 ₽**, задаток **327 400.00 ₽**, кадастровый номер `77:01:0004002:6633`, площадь 13.3 м².
- Цены совпадают **законно по сведениям источника**, но ID, площади и кадастровые номера различаются. Нельзя создавать одну карточку с ID `502957` для этих 10 объектов и нельзя раздавать им общую цену из заголовка процедуры.

Полная копия предоставлена пользователем как **текст страницы**, а не как сырая HTML-разметка. Сессионные cookie, контакты, реквизиты и авторизационная информация в этот PR не добавлены.

## Проверено кодом

- Добавлен **чистый, не выполняющий запросов** `nistp_detail_sections.py` и тесты на десять отдельных секций.
- Секция признаётся валидной лишь при совпадении двух маркеров `Лот № N` и `Номер лота N`; другие упоминания номеров лотов не считаются секциями.
- Раздельные значения `начальная цена` / `размер задатка`, цены проверяются `Decimal` и до копейки; статус, описание, кадастровый номер и площадь читаются только в границах соответствующей секции.
- Повтор номера, отсутствующий номер запроса, неполная секция, отсутствующая цена, невалидный ID или несоответствие номера лота — диагностическая ошибка (fail-closed).
- Поддержка реального HTML ещё **не доказана**, поскольку у нас есть лишь browser-visible text. Настоящий сетевой ответ может содержать другое разделение HTML-элементов.

## Что намеренно НЕ изменено

- **Не включали** `fetch_lot`/`detail_enrichment` НИСТП в production connector: это остаётся заблокировано, пока не проверен реальный сохранённый HTML страницы с `trade_nid=502957`.
- Не меняли `main`, ручной/плановый Home обход, базу, GEO, MapDataset, S3, политику архивирования.
- Не заявляли приёмку всех лотов или доказанную последнюю страницу.

# BankrotAI — ТЗ на дизайн раздела «Надёжность»

**Версия:** 1.0  
**Дата:** 19.11.2026  
**Основа аудита:** `main@bbc3d75018d281aca3ef938c1c360fc5c8519413`

## 1. Цель

Раздел «Надёжность» должен за 10 секунд отвечать на три вопроса:

1. Работает ли система нормально, с ограничениями или находится в инциденте?
2. Насколько свежи и полны данные?
3. Что требует внимания и какое действие выполнить дальше?

Основной UI полностью русскоязычный. Технические enum допускаются только в раскрываемых технических деталях.

## 2. Подтверждённые проблемы старого интерфейса

| Проблема | Почему это неверно |
|---|---|
| «Сеть источников стабильна» | Отражала только global network circuit и могла быть зелёной при stale/failed источниках |
| «Источники 0/0» | Знаменатель исключал paused источники и выглядел как отсутствие источников |
| healthy + старая ошибка | Историческая ошибка показывалась как текущая после более позднего success |
| `closed`, `half_open` | Пользователю показывались технические состояния circuit breaker |
| GEO current vs historical | 79k текущих координат визуально смешивались со 128k исторических GEO snapshots |
| «Полнота данных» | Сырые английские ключи и показатели всей исторической таблицы |
| Runner | Возраст диагностического snapshot выдавался за состояние runner online/offline |
| Карта ready | `MapDataset.status=ready` не доказывает целостность DB → Dataset → S3 → Public |
| Дубли источников | Исторические alias source_system создавали отдельные строки |

## 3. Визуальная концепция

- Спокойная операционная панель, белый фон, тонкие границы, минимум декоративных теней.
- Desktop: max-width рабочего пространства приложения, KPI 4 колонки, 16 px между блоками.
- Tablet: 2 колонки.
- Mobile: 1 колонка.
- Числа: формат `126 057`; проценты — максимум один знак после запятой.
- Статус всегда дублируется цветом, текстом и/или иконкой.
- Контраст текста — WCAG AA.

### Статусы

| Статус | Цвет | Текст |
|---|---|---|
| ok | зелёный | Система работает нормально |
| degraded | оранжевый | Работает с ограничениями |
| incident | красный | Требуется вмешательство |
| paused | серый | На паузе |
| unknown | серый контур | Нет свежей проверки |

### Русские названия технических состояний

| Код | UI |
|---|---|
| healthy | Норма |
| degraded | Требует внимания |
| failed | Ошибка |
| fresh | Актуально |
| delayed | Есть задержка |
| stale | Устарело |
| missing | Полного снимка нет |
| partial | Частично выполнено |
| closed | Соединение разрешено |
| open | Временно отключён |
| half_open | Проверка восстановления |
| actionable | Требует обработки |
| deferred_no_match | Соответствие не найдено |
| deferred_validation | Не прошло проверку |
| network_wait | Ожидание сети |

## 4. Структура экрана

Порядок блоков фиксированный:

1. Общий статус.
2. 8 ключевых KPI.
3. «Требует внимания».
4. Источники.
5. GEO.
6. Карта.
7. Полнота и качество данных.
8. Инфраструктура.
9. Целостность данных.
10. Журнал.
11. Диагностика.

Верх экрана показывает только текущее состояние. Исторические данные не должны влиять на пользовательское восприятие текущего health.

## 5. Общий статус

Карточка содержит:

- статус: «Система работает нормально» / «Работает с ограничениями» / «Требуется вмешательство»;
- не более двух главных причин в hero;
- время обновления;
- deployment SHA;
- schema revision.

Глобальный статус запрещено рассчитывать только по network circuit.

## 6. KPI

Обязательные карточки:

1. **Источники** — `fresh complete / configured`; отдельно ошибки и paused.
2. **Свежесть данных** — возраст полного подтверждённого снимка.
3. **GEO** — current geocoded / GEO population.
4. **Карта** — point count и статус полной доставки.
5. **Целостность** — число критических классов и предупреждений.
6. **Инфраструктура** — API, DB, queue, runner diagnostics.
7. **Backup** — возраст и restore verification.
8. **Диск** — свободное место; ≥25 ГБ норма, 15–25 предупреждение, <15 критично.

## 7. «Требует внимания»

- Блок всегда выше длинного списка источников.
- Содержит только актуальные проблемы.
- Приоритет: critical → warning → info.
- Каждая проблема имеет ссылку «Открыть» на соответствующий блок.
- Историческая ошибка после успешного прохода сюда не попадает.
- Retry в прошлом отображается как «Повтор просрочен».

## 8. Источники

Одна строка на canonical source.

Фильтры:

- Требуют внимания;
- Все;
- Актуальные;
- На паузе;
- Пилотные.

Колонки:

- источник;
- состояние;
- последний успех;
- полный снимок;
- число записей в БД;
- текущая проблема;
- раскрытие подробностей.

В раскрытии:

- свежесть;
- circuit breaker в русском переводе;
- последний проход;
- следующий retry;
- aliases;
- текущая ошибка;
- последняя историческая ошибка;
- admin-действие «Проверить источник», если deployment допускает background jobs.

## 9. GEO

Один scope:

> Актуальные неархивные primary-публикации, где есть адрес или кадастровый номер.

Показывать:

- population;
- текущие координаты;
- процент;
- требует обработки/повторной проверки;
- no match;
- validation;
- network wait;
- недостаточно входных данных;
- исторически имели GEO snapshot.

Historical GEO не использовать как KPI текущего покрытия.

## 10. Карта

Показывать цепочку:

**База данных → MapDataset → S3 manifest → публичная выдача**

Зелёный статус разрешён только после полной reconciliation.

Дополнительно:

- DB eligible count;
- dataset unique lot count;
- missing;
- extra;
- dataset version;
- published_at.

## 11. Полнота и качество данных

Основной scope:

> primary + non-archived + non-ended публикации.

Для каждого показателя показывать count + percent:

- без адреса;
- без кадастра;
- без цены;
- unknown status;
- без региона;
- без URL;
- неположительная цена.

Общий исторический total вынести отдельной строкой.

`ai_analyzed_lots` и `document_versions` не относятся к reliability и не выводятся в этом блоке.

## 12. Инфраструктура

Показывать отдельно:

- API;
- БД;
- очередь;
- диск;
- backup;
- диагностика runner.

Runner snapshot прямо подписывать как диагностику, а не online/offline.

## 13. Журнал

До 50 последних событий.

Фильтры:

- Все;
- Ошибки;
- Источники;
- GEO;
- Карта;
- Инфраструктура.

Строка: severity, компонент, сообщение, точное время.

## 14. Диагностика

Не выводить raw JSON на страницу.

Admin-кнопки:

- «Скачать diagnostics.json»;
- «Копировать».

В read-only deployment write-actions скрываются/недоступны с понятным пояснением.

## 15. Loading / error states

- На первичной загрузке — loader/skeleton, не фальшивые нули.
- Ошибка одного блока не должна скрывать последний успешный snapshot остальных.
- «Нет данных» отображается как «Проверка ещё не выполнялась».
- Автообновление — каждые 30 секунд.
- Ручная кнопка обновления одна — в page header.

## 16. Адаптивность

- ≥1200: полноценная таблица источников.
- 768–1199: KPI 2 колонки, source table упрощается.
- <768: 1 колонка, детали источника раскрываются.
- 390 px: без горизонтального переполнения основного контента.

## 17. Критерии приёмки

- Нет raw enum в primary UI.
- Нет зелёного общего статуса при критически stale/failed обязательных компонентах.
- Нет бессмысленного `0/0`.
- Current error и historical error разведены.
- Canonical aliases не дублируют источники.
- GEO current/history не смешаны.
- Карта зелёная только после delivery reconciliation.
- Проблемный источник находится без прокрутки всех healthy.
- Каждое важное предупреждение имеет следующий шаг.
- Diagnostics скачивается, а не рендерится raw JSON.

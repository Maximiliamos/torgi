# TORGI ETP — результаты Smart Capture v3, 29.10.2026

Источник: локальный архив пользователя `TORGI_ETP_SMART_20261029_012825.zip`. Исходные HTML, сетевые тела, изображения и персональные сведения сторон торгов **не добавляются в GitHub**. Подтверждения ниже относятся только к моменту записи; они не гарантируют полный реестр.

## Итог

- Обследовано 22 публичных ЭТП. У 17 обнаружены страницы каталогов с потенциальными карточками; для 15 доказано появление новых URL лотов после перехода на страницу 2.
- Записаны 50 HTML-страниц с URL предполагаемых карточек, но три страницы Сбербанк-АСТ показывают в основном общую навигацию сайта, **а не подтверждённые детали лота**. Проверка качества HTML для них не пройдена.
- Архив содержит 568 текстовых XHR/Fetch-тел; часть — JavaScript, CSS и вспомогательные запросы, не пригодные как контракт каталога.
- Все результаты имеют `complete_source_inventory=false`; ни одна площадка не должна автоматически архивировать исчезнувшие лоты или обновлять production на основании этого обследования.

## Сверка реальных JSON с `captured_etp_api.py`

- **ЦДТ:** `GET /api/Trade/trades` с `Declare=true&RecieveReq=true&PageSize=20&PageNum=1` и `PageNum=2` возвращает по 20 записей; обе страницы подтверждены, текущий `totalCount=10456`. Существующий валидатор выделяет **12 + 13 = 25 предварительных кандидатов недвижимости** по справочнику категорий. Это не полное количество недвижимости на площадке. Не использовать поле `name` в качестве названия лота: в данном контракте это имя должника.
- **Сбербанк-АСТ:** `POST /api/Processing/main`, `windowCode=/ESGoodsList`, `sourceTerm=Продажа имущества (предприятия) банкротов`, `pagesize=21`, `pagenum=0` и `pagenum=1`. Обе сохранённые страницы возвращают `Total=375`, 21 позицию каждая. Валидатор принимает **7 + 5 = 12 предварительных кандидатов** из категории `Недвижимое имущество`. Тело ответа без `sourceTerm` указывает `Total=10000` и не является банкротным каталогом. 375 — общий результат фильтра, а не 375 объектов недвижимости.
- Для Сбербанк-АСТ ссылки `/Catalog/NBT/GoodsView/...` могут открывать страницу-оболочку без цены и идентифицируемого объекта; не считать один URL подтверждённой детальной карточкой и не подставлять данные карточек из других разделов.

## Проблемы и безопасные действия

| ЭТП | Что наблюдалось | Действия |
| --- | --- | --- |
| РТС-тендер | Anti-DDoS-проверка оставалась 45 секунд без автоматического перехода | Пассивное ожидание с таймаутом до 90–180 секунд, без обхода защиты |
| uTender | `ERR_SSL_VERSION_OR_CIPHER_MISMATCH` | Отметить ошибку SSL, не отключать проверку TLS |
| Electro-torgi | HTTP 429 | Остановиться, не выполнять автоматических повторов |
| Профит | Конечная страница оказалась главной, каталог не подтверждён | Повторно проверить публичную ссылку `/etp/trade/list.html` |
| Аукционы Сибири | Каталог не распознан, главная содержит `/etp/trade/list.html` | Проверить данный маршрут и зафиксировать цепочку редиректов |

## Следующий технический шаг

1. Обход пагинации в ограниченном режиме и сверка `source_id`/`trade_id`/`lot_id` по каждой реальной карточке.
2. Для ЦДТ и Сбербанк-АСТ читать детали с доказанной идентичностью, статусом, сроками и ценой; не подменять текущую цену начальной или будущей.
3. Проверить дедупликацию с ЕФРСБ и ГИС Торги, геокодирование, журнал событий и изменения статусов в изолированной БД.
4. Провести PostgreSQL/SQLite/WEB интеграционные тесты и отдельный controlled-rollout, запретить архивирование до нескольких полных циклов проверки.

Диагностический сборщик v4 исправляет ложные HTML-детали Сбербанк-АСТ, фильтрует сетевые ассеты, записывает попытки навигации и доказательства отличия страниц. Он распространяется отдельно от production TORGI и не подключает новые площадки к Celery автоматически.

# TORGI — пакет прямых ЭТП: 20 запрошенных + Lot-online и UTPL

**Принятое решение:** сначала подготовить все адаптеры и единый диагностический запуск, затем один раз запустить проверку всех площадок на домашнем Windows ПК. Это не означает, что наличие 22 адресов сайтов уже доказывает 20 полноценных парсеров. Разделяем готовые механизмы извлечения, находящиеся в исследовании интерфейсы и давно подключённые источники.

## Разграничение готовности

- `table_lots`: на публичной странице есть отдельная строка лота; parser выдаёт кандидата с источником, номером процедуры/лота, ценой и ссылкой. Данные **не проверены** по карточке.
- `trade_rows`: строка содержит торги и несколько лотов. Разделяем по `Лот №`; цену/статус конкретного лота пока не утверждаем.
- `verdict_lots`: предварительный разбор строк отдельной секции арестованного имущества «Вердиктъ».
- `alfalot_lots`: отдельные lot-card ссылки и устойчивые trade+lot номера из публичной таблицы; цена до чтения detail не подтверждается.
- `links`: только если виден явно размеченный номер торгов и лота. При динамическом фронтенде может вернуть 0, это не доказательство отсутствия торгов.
- `research`: маршруты реестра не проверены; никакие фиктивные лоты не создаются.
- `existing`: используются уже существующие отдельные парсеры; двойной сбор запрещён.

## Единый диагностический запуск после завершения кодирования

В отдельной тестовой копии соответствующей ветки, не в папке `C:\Users\Максим`:

```powershell
$env:PYTHONPATH = "src"
python scripts/probe_direct_etps.py --confirm-public-network --max-candidates-per-site 20 --delay-seconds 1 --output direct-etps-report.json
```

Один запуск сформирует матрицу 22 профилей (20 запрошенных ЭТП + Lot-online + UTPL). Каждый источник проверяется отдельно и не останавливает остальные при 403, 429, ошибке парсинга или отсутствующем HTML. Никакой обход CAPTCHA, доступа, регистрации, антибота или ограничений запросов не реализован.

**На текущей стадии скрипт не доказывает полноту 22 профиля:** он получает один публичный каталог для известных маршрутов, не выполняет реестр всех страниц, не вычисляет пропущенные объявления и не пишет в PostgreSQL. Результаты не должны использоваться для подсчёта полной загрузки или архивирования.

## Условия включения в production после совместного теста

1. У каждого источника подтвердить полную пагинацию и устойчивую идентичность лота и повторных стадий торгов.
2. Разобрать детали по исходной карточке: цена, актуальность публичного предложения, все сроки, статус и кадастровые номера; не путать события торгов с отдельными лотами.
3. Сопоставить с текущей БД TORGI на примерах реальных объектов и измерить количество новых уникальных лотов.
4. Добавить тестовые снимки для изменяющихся макетов и не допускать тихого уменьшения покрытия.
5. Только после приёмки сделать отдельный rollout с отключённым архивированием для новых ЭТП, затем контролировать качество несколько полных циклов.

## Режим безопасности

Ни один источник в этом PR не внесён в `default_source_specs`; автоархивирование, изменение PostgreSQL, публикация карты и S3 отключены. Использование существующих API/парсеров TORGI для ГИС Торги, Lot-online и агрегаторов не меняется. Не выполнять слияние в main: это вызывает автоматическое развёртывание Home/REG.RU/Cloudflare.

## ЦДТ: разбор двух HTML-снимков 28 октября 2026 года

Пользователь предоставил сохранённые страницы `https://torgi.cdtrf.ru/` и `https://torgi.cdtrf.ru/trades/390364`. Они показали 20 карточек первой страницы и 377303 записей в интерфейсе на момент сохранения. Это **не актуальный полный счётчик торгов** и не подтверждение 377303 доступных объектов недвижимости. Навигация 1–18866 реализована кнопками без href: для полного обхода требуется контракт XHR/Fetch второй страницы.

Реальная карточка: `tradeId=390364`, `tradeLotId=390899`, `lotNumber=1`, `regionID=32`, цена 675000 руб., статус `Declare` («Торги объявлены»); даты приёма 29.10–02.12.2026. Для публичного предложения сохранены **семь ценовых периодов** от 675000 до 270000 руб. Из поля координат приходит `0.0000000, 0.0000000`; это не геолокация. Отсутствующие координаты нельзя считать точкой в Гвинейском заливе.

Код `src/bankrotai/connectors/registry/cdtrf_public.py` валидирует соответствие URL, DOM и Nuxt JSON, сохраняет ID торга отдельно от ID лота, читает даты и цены без дедукции конечного статуса. В каталоге `tradeLotId` неизвестен до открытия детали, поэтому `ready_for_ingestion=false`. Интегрировано в общий read-only batch source `cdtrf.ru`.

Локальная проверка двух файлов без сетевых запросов:

```powershell
$env:PYTHONPATH = "src"
python scripts/probe_cdtrf_saved_html.py --catalog "C:\path\catalog.html" --detail "C:\path\detail.html" --detail-url "https://torgi.cdtrf.ru/trades/390364" --output cdtrf-evidence.json
```

Чувствительные сведения из документа (ФИО, контакты, полный юридический текст) в GitHub **не добавлялись**. Тесты используют синтетические минимальные HTML/Nuxt фрагменты. Полный импорт ЦДТ, архивирование и интеграция в график Celery до подтверждения сквозной пагинации запрещены.


## Сбербанк-АСТ: анализ двух снимков от 28 октября 2026 года

Пользователь предоставил два HTML файла, сохранённых в браузере:

1. Общий \`https://www.sberbank-ast.ru/UnitedPurchaseList.html\` — в сохранённом результате **20 карточек госзакупок по 44-ФЗ**, ни одного URL формата \`/Property/NBT/PurchaseView/\`. Это не подходящий реестр объектов недвижимости для TORGI. На этой странице есть отдельные навигационные ссылки на коммерческое имущество \`https://www.sberbank-ast.ru/sales/SaleProperty.html\` и имущество банкротов \`https://www.sberbank-ast.ru/sales/SaleBankruptProperty.html\`, но их пагинированный каталог в присланных HTML не представлен.
2. Карточка непосредственной УТП \`https://utp.sberbank-ast.ru/Property/NBT/PurchaseView/30/0/0/4271626\`. Наблюдаемые значения: ID страницы процедуры \`4271626\`, номер процедуры \`SBR065-2610280004\`, **отдельный ID лота \`3448676\`**, лот \`1\`, статус «Прием заявок», тип «Голландский аукцион (с ЭП)», категория «Имущественный комплекс», Ставропольский край, старт 2050800 руб., цена отсечения 1367200 руб., задаток 205080 руб., площадь объекта 141,90 м², земли 236,87 м². Приём заявок 28.10.2026 15:00 — 28.01.2027 15:00; начало торгов 01.02.2027 10:00. Цена в **11 периодах** снижается на 68360 руб. от 2050800 до 1367200 руб. По снимку нельзя утверждать, что любая из будущих цен сейчас действует.

Добавлен \`src/bankrotai/connectors/registry/sber_ast_property.py\`: разбор без JavaScript из полей \`PurchaseInfoView_*\`, \`Bids_*\`, \`PurchasePlan_*\`, строгий канонический URL без сторонних хостов, разделение ID лота/процедуры, извлечение графика, проверка противоречий, **запрет на выдуманную текущую цену и координаты**. Документы сохраняются только как имена; не извлекаются контакты/банковские реквизиты/токены. Входные HTML-файлы пользователя в GitHub не помещались. Test-fixtures полностью синтетические.

python scripts/probe_sber_ast_saved_html.py --united-list "C:\path\UnitedPurchaseList.html" --detail "C:\path\PropertyPurchaseView.html" --detail-url "https://utp.sberbank-ast.ru/Property/NBT/PurchaseView/30/0/0/4271626" --output sber-ast-evidence.json

**Не готово:** достоверный список всех имущественных лотов, страницы реестра \`Property\` и \`Bankruptcy\`, обработка пагинации/фильтров и сравнение количества страниц. Поэтому статус профиля пока \`research\`; новый источник не активировать в production/Celery, не архивировать пропавшие записи, не публиковать карту по одному сохранённому снимку.

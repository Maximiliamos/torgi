# Техническое задание: дизайн раздела «Надёжность»

Версия 1.0 · 19.11.2026 · BankrotAI Web  
Основание: перепроверка WEB/src/main.tsx, WEB/src/lib/api.ts, WEB/src/styles.css, src/bankrotai/api.py и сервисов мониторинга.  
**Приоритет:** корректность смысла показателей выше декоративного оформления.

## 1. Цель
За 10 секунд пользователь должен понять: работает ли система, какие проблемы актуальны, насколько свежи данные, что проверено и что требует действия. Основной язык — русский. Сырые технические enum не допускаются в основном интерфейсе.

## 2. Иерархия
1. **Общий статус:** «Система работает нормально» / «Работает с ограничениями» / «Требуется вмешательство» / «Нет свежих данных». Время последнего обновления, версия deployment и 1–2 главные причины.
2. **KPI:** источники, свежесть полного прохода, GEO, карта, целостность БД, инфраструктура, backup, диск.
3. **Требует внимания:** актуальные проблемы, сортировка по критичности; не показывать старую ошибку после нового успешного прохода.
4. **Источники:** поиск, фильтры, сортировка; статус, последний успех, свежесть, полнота снимка, статистика прохода, повтор, раскрываемая диагностика.
5. **GEO:** текущая выборка, с координатами, требуют обработки, отложены по причинам. Исторические GEO-снимки — отдельно.
6. **Карта:** БД → MapDataset → S3 manifest → публичная выдача → сверка. Dataset ready сам по себе не означает успешную доставку.
7. **Качество данных:** текущие неархивные primary-публикации и проценты с единым знаменателем; историческая база — отдельно.
8. **Инфраструктура:** API, БД, очередь, runner diagnostic, backup, диск.
9. **Журнал и диагностика:** последние события, скачивание JSON, без raw JSON в основном экране.

## 3. Терминология
| Backend | Русская подпись |
|---|---|
| healthy / success | Норма / Успешно |
| partial | Частично |
| failed | Ошибка |
| fresh | Актуально |
| delayed | С задержкой |
| stale | Устарело |
| missing | Нет полного снимка |
| closed (circuit) | Соединение разрешено |
| open (circuit) | Соединение отключено |
| half_open | Проверка восстановления |
| paused | На паузе |
| actionable | Требует обработки |
| deferred_no_match | Соответствие не найдено |
| deferred_validation | Не прошло проверку |
| network_wait | Ожидание сети |

Не путать **closed (circuit)** и закрытый аукцион; не путать **ready (MapDataset)** с публикацией в S3.

## 4. Визуальная система
- Светлый нейтральный фон, спокойные карточки, одна система отступов (8/12/16/24 px), radius 10–12 px.
- Desktop max-width 1440 px, 12-колоночная сетка; tablet — две колонки; mobile — одна.
- Заголовок 28–32 px, секции 18–20 px, KPI 24–30 px, основной текст 13–14 px.
- Зелёный = норма; оранжевый = ограничения; красный = инцидент; серый = пауза/нет данных. Текст и иконка обязательны: цвет не единственный сигнал.
- Русские числа с пробелами между тысячами; время «N минут назад» и точное московское время.
- Контраст ≥ 4,5:1, keyboard focus, aria-label, состояния загрузки/ошибок/пустой выборки.

## 5. Правила точности
- Счётчик источников **обязан различать** настроенные, плановые, пилотные и исторические. «0/0» не трактовать как отсутствие источников.
- Общий статус не может определяться только global network circuit.
- Старую ошибку после более позднего успеха показывать только в истории.
- GEO current coordinates и historical LotGeoSnapshot — разные метрики.
- Runner snapshot age не является подтверждением online/offline.
- Backup «Проверен» — только если есть успешная restore verification.
- Для карты зелёный статус только после сверки DB/manifest/public.
- Исторические показатели качества не использовать как текущие KPI.

## 6. Приёмка дизайна
1. Основной UI полностью на русском; неизвестные enum — «Неизвестно», raw только в деталях.
2. Все KPI имеют scope, дату и источник определения.
3. Проблемы видны выше длинных таблиц; фильтры и поиск работают.
4. Нет ложного зелёного статуса при failed/stale источниках.
5. Нет ложного утверждения о доставке карты по одному Dataset.status.
6. 390 px mobile без горизонтального переполнения.
7. Недоступные в read-only действия скрыты или явно заблокированы.
8. Дизайн согласован с контрактом backend и проверен на реальных данных.

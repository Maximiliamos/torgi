# REG.RU S3 — инвентаризация перед очисткой

Не удалять `bundles`, `indexes`, `datasets` вручную: разные версии карты ссылаются на общие объекты.

28.10.2026: 9,45 ГБ и 212 092 объекта в `sterdez-map`; общая квота уже увеличена до 20 ГБ.

Скрипт `scripts/plan_reg_s3_orphans.py` **не делает запросов в сеть и не удаляет данные**. Работает только с полным инвентарём S3 и со всеми существующими dataset manifests. Любое нарушение полноты — ошибка; объекты младше 30 дней и объекты, на которые ссылается любой manifest, сохраняются.

## Как собрать данные

На локальном компьютере с установленным S3-совместимым CLI, настроенным на *endpoint REG.RU* (ниже AWS CLI выступает клиентом REG.RU, не AWS):

```powershell
aws --endpoint-url $env:S3_ENDPOINT s3api list-objects-v2 --bucket sterdez-map --output json > s3-inventory.json
```

Проверить отсутствие `IsTruncated: true` и неполных страниц. Для каждого `datasets/<VERSION>/manifest.json` из полного инвентаря скачать JSON в локальную папку `s3-manifests/<VERSION>.json`. Не пропускать старые версии. Ключи доступа держать только в локальной конфигурации.

```powershell
python scripts/plan_reg_s3_orphans.py --inventory s3-inventory.json --manifests s3-manifests --output s3-orphans-plan.json
```

Полученный список кандидатов — только отчёт, **не разрешение удалять**. Понадобятся проверка активной версии, rollback, повторное сравнение с S3 и отдельное одобрение ограниченной операции удаления. В GitHub не загружать инвентарь, ключи или приватные метаданные.


## Ограничения доказательств

Планировщик требует `IsTruncated: false` и отсутствие `NextContinuationToken`, полное соответствие inventory и *всем* сохранённым manifest, корректные размеры объектов и даты в часовом поясе. Отсутствие флага полноты — **ошибка**, а не разрешение считать объекты неиспользуемыми. Если AWS CLI собрал несколько страниц, оператору необходимо самостоятельно проверить, что итоговый JSON действительно полный и метаданные сохранены. Без этого **не использовать** результат для удаления.

Скрипт не может доказать отсутствие ссылок из CDN/cache, сторонних версий клиента, ещё не опубликованных наборов и ручных rollback-точек. Поэтому даже корректный вывод `candidate_count > 0` означает только список для дальнейшей проверки. Никаких команд удаления в этой реализации нет.

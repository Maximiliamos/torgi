# ЕФРСБ — официальный REST API, безопасный пилот (1.4.0, 19.02.2026)

**Статус:** интеграция официального API реализована только для чтения публикаций; TORGI пока не создаёт из них лоты, не удаляет данные и не публикует карту. Это сознательное ограничение: сообщение ЭТП может содержать сведения о нескольких лотах, а GUID сообщения не является идентификатором продаваемого объекта.

Документация оператора: https://fedresurs-demo.interfax.ru/helps/bankrupt/Service_rest_1.4.0.pdf
Swagger demo: https://bank-publications-demo.fedresurs.ru/swagger/index.html
Swagger production: https://bank-publications-prod.fedresurs.ru/swagger/index.html

## Что исправлено

- `v1/auth`: JSON `login` + `password` по HTTPS без старого SHA-512; `jwt` используется с Bearer и обновляется до истечения восьми часов.
- `v1/messages` — сообщения участников ЕФРСБ, в том числе объявления торгов. `v1/trade-messages` — сообщения электронных площадок о ходе торгов. Не путать с уникальными лотами.
- `pageData` + `total`, `limit` + `offset`; запросы публикаций за период до 31 дня. Пилот имеет жёсткий лимит страниц, обнаруживает повторы и неверный `total`, не объявляет усечённую выдачу полной.
- Для тестового и промышленного API разрешены только два официальных домена. Редиректы запрещены, пароль и JWT в отчёты не попадают.
- `FedresursConnector.search()` и `fetch_lot()` теперь отказываются преобразовывать сообщения в лоты, поскольку текущая реализация не поддерживает доказанную XML-декомпозицию и идентичность лотов.

## 1. Получение доступа

Промышленный доступ требует собственного договора/учётных данных у оператора. Не выкладывать логин, пароль и JWT в GitHub, issues, логи или переписку.

Тестовый контур и демонстрационная учётная запись приведены в официальной спецификации (п. 1.3, стр. 7 и п. 2.1.2). Вставьте реквизиты на ПК локально — в GitHub их нет.

## 2. Тест на Windows без записи в БД

Из PowerShell в рабочем venv после установки зависимостей проекта:

```powershell
$env:PYTHONPATH = "src"
$env:FEDRESURS_LOGIN = Read-Host "EFRSB test login"
$secret = Read-Host "EFRSB test password" -AsSecureString
$env:FEDRESURS_PASSWORD = [System.Net.NetworkCredential]::new("", $secret).Password
python scripts/probe_fedresurs_official.py --environment demo --kind trade-messages --start 2026-10-27 --end 2026-10-27 --page-size 50 --max-pages 2 --confirm-network-access --output fedresurs-pilot.json
Remove-Item Env:FEDRESURS_PASSWORD,Env:FEDRESURS_LOGIN -ErrorAction SilentlyContinue
```

Отчёт `fedresurs-pilot.json` содержит только идентификаторы событий, номера торгов, типы публикаций, даты и признаки блокировки. Он **не включает XML**, документы, имена должников, токены и пароли. Если `complete=false`, лимит пилота ограничил выдачу — не использовать её для архивирования.

Для сообщений об объявлении торгов поменять `--kind messages --types Auction`. Названия типов подтверждать по справочнику оператора. Для реального API поменять `--environment production` и использовать только персональные реквизиты, выданные оператором.

## 3. Что требуется для реального включения в TORGI

1. Подтвердить промышленный доступ и разрешённый объём API запросов; сравнить точный контракт с XML-схемами ЕФРСБ и ЭТП.
2. Построить `EFRSBMessage`/`EFRSBTradeEvent` со связями по GUID, `auctionMessageGuid`, `trade.guid`, `trade.number` и истории аннулирования; с учётом PII и условий доступа.
3. Разобрать SOAP/XML с защитой от внешних сущностей; выделять **каждый** лот с собственным стабильным ключом: `tradeGUID + lotNumber`, а не message GUID. Сопоставить источник с текущим `CanonicalLot` только на доказанной идентичности.
4. Отдельная тестовая схема PostgreSQL, dry-run/diff по статусам и ценам; не делать массового архивирования по отсутствию ЕФРСБ публикаций. Не изменять текущие пять источников до завершения приёмки.
5. Лишь после сравнения с первичными ЭТП и успешных тестов включать расписание, с bounded lookback/watermark и мониторингом ошибок.

**Промышленная интеграция не считается запущенной** до получения личных реквизитов, живого smoke-теста на Home и подтверждения XML-структуры лотов.

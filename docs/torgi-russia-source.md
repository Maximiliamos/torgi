# «Торги России»: persistent ingestion после обновления сайта

Проверено 27 сентября 2026 года по сохранённой публичной странице нового сайта
`https://торги-россии.рф`.

## Что изменилось

Новая версия сайта работает на Next.js/Turbopack и серверно встраивает данные в
React Flight payload вида `self.__next_f.push(...)`.

В публичном HTML присутствуют полноценные объекты лотов, включая:

- `id`;
- `title`;
- `status`;
- `pictures`;
- `start_price` и `current_price`;
- `region`;
- `marketplace`;
- `trade_type` и `trade_form`;
- `trade_link`;
- `category_ids`.

Стабильные публичные URL карточек остались вида `/lot/{numeric_id}`.
Ссылки категорий нового сайта используют `/search?search=&categorie_childs[]=...`.

На странице также присутствует отдельная ссылка «Старая версия сайта», что
подтверждает переход на новый frontend.

## Текущая стратегия BankrotAI

Основной путь ingestion больше не зависит от старого backend
`апи.торги-россии.рф/api`, который в production начал отвечать тайм-аутами.

Текущий путь:

1. GET публичной страницы `/search`.
2. Разбор Next.js Flight payload из `self.__next_f`.
3. Извлечение объектов лотов и сверка с публичными `/lot/{id}` ссылками.
4. Нормализация в существующие `torgi-russia:{numeric_id}`, поэтому миграция
   идентификаторов в БД не требуется.
5. Пагинация публичного каталога через `page=N`.
6. Detail enrichment выполняется через публичную `/lot/{id}` страницу, а не
   через старый API-host.

Если серверная пагинация не публикует явную ссылку на следующую страницу,
используется безопасный fallback по размеру страницы: полный 20-элементный
ответ допускает ещё один запрос. Лишняя пустая страница безопаснее тихого
обрезания источника.

## Ограничения

Проект не обходит CAPTCHA, anti-bot protection или access controls. При
HTTP 403/429 или другом явном ограничении источник должен завершаться
fail-closed и не архивировать отсутствующие лоты.

Полный source reconciliation считается доказанным только после production
прогона нового публичного transport.

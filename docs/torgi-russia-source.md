# «Торги России»: persistent ingestion после обновления сайта

Проверено 27–28 сентября 2026 года по сохранённой публичной странице новой вкладки
«Недвижимость» сайта `https://торги-россии.рф`.

## Что подтверждено сохранённым каталогом

Новая версия работает на Next.js/Turbopack и серверно встраивает данные в
React Flight payload `self.__next_f.push(...)`.

Реальная вкладка недвижимости использует семь дочерних категорий:

- 7;
- 33;
- 343;
- 9;
- 18;
- 17;
- 16.

SSR payload содержит `initialLots` и `initialMeta`. На проверенной первой
странице:

- `per_page = 24`;
- `last_page = 209`;
- `total = 5000` — это лимит выдачи одного запроса;
- `lots_amount_active_only = 25799` — активных лотов существенно больше лимита.

Объект лота новой страницы содержит, среди прочего:

- `id`;
- `title`;
- `status` и `status_id`;
- `pictures[].url`;
- `start_price` и `current_price`;
- `region_title`;
- `marketplace_title`;
- `trade_type_title` и `trade_form`;
- `category_ids`.

Стабильные публичные URL карточек остались вида `/lot/{numeric_id}`, поэтому
существующие идентификаторы `torgi-russia:{numeric_id}` не меняются.

## Текущая стратегия BankrotAI

Основной ingestion больше не зависит от старого backend
`апи.торги-россии.рф/api`, который в production начал отвечать тайм-аутами.

Текущий путь:

1. GET публичной страницы `/search`.
2. Разбор `initialLots` и `initialMeta` из Next.js Flight payload.
3. Нормализация новой схемы (`region_title`, `pictures[].url`, строковый
   `status`) с сохранением прежних external ID.
4. Использование фактического размера страницы 24.
5. Поскольку одна выдача ограничена 5000 лотами, полный nationwide ingestion
   сегментируется по внутренним `regions[]` ID публичного каталога. Live-probe
   28 сентября подтвердил, что ID 1–79 совпадают с привычной первой частью
   справочника, а хвост является последовательным source-списком:
   `80=Ненецкий АО`, `81=ХМАО`, `82=Чукотка`, `83=ЯНАО`,
   `84=Республика Крым`, `85=Севастополь`,
   `86=Иные территории, включая город и космодром Байконур`.
   Значения 87–99 на текущем public search возвращают пустую выдачу.
6. Каждый региональный запрос проверяется fail-closed с учётом этого mapping:
   если сервер вернул распознаваемые лоты другого региона или bucket 86 вернул
   не «Иные территории», reconciliation прекращается и ничего отсутствующее
   не архивируется.
   распознаваемые лоты другого региона, reconciliation прекращается и ничего
   отсутствующее не архивируется.
7. Detail enrichment выполняется через публичную `/lot/{id}` страницу.
   Версии detail enrichment 3 и 4 считаются совместимыми, чтобы migration
   transport не вызвала массовое повторное скачивание десятков тысяч карточек.

## Безопасность reconciliation

Публичный каталог сообщает больше активных лотов, чем допускает один search
result, поэтому unsegmented 5000-row проход нельзя считать полным источником.

Полный source reconciliation считается доказанным только после production
прогона регионально сегментированного public transport. Проект не обходит
CAPTCHA, anti-bot protection или access controls. HTTP 403/429, тайм-аут,
неприменённый региональный фильтр или неполная пагинация должны завершаться
fail-closed и не архивировать отсутствующие лоты.

Дата среза: 18 ноября 2026. Основание — исходные 44 обращения по 41 лоту,
полный внутренний аудит 239676 ProcessedLot и проверки первичных площадок.
Кандидат детектора не считается ошибкой до проверки источника.

## Доказательства и ограничения

- Приватные артефакты: `.artifacts/finish/systemic-database-baseline.json`,
  `systemic-database-after-1181-repairs.json`, `reports-resolution-audit.json`,
  `tbankrot-safe-*-result.json`, `gov-safe-20261118a-*-result.json`,
  `gov-entire-verified/manifest.json`, `geo-p0-current-20261118.json`.
- Для всех 44 исходных обращений есть индивидуальный outcome; 38 уникальных
  лотов удалены по прямому указанию пользователя, 3 исправлены. Это история
  обработки обращений, а не доказательство устранения всех классов дефектов.
- TBankrot остановлен после HTTP 429. У сохранённых карточек нет достаточных
  procedure/lot ссылок для точного массового соединения с первичными ETP.
  Один совпавший кадастр не разрешает перенос цены, дат и статуса.
- Собранные GIS доказательства покрывают доступные поля точных карточек.
  Пустые поля, фотографии вне XLSX и последующие изменения источника остаются
  отдельными ограничениями. Сбор не равен применению и проверке результата.
- Все новые исправления сохраняют оценки/заметки; проверки digest входят
  в ограниченные транзакции. Новых массовых удалений по кандидатам нет.
- Начата read-only проверка всех 11323 уникальных кадастров для 13083
  подходящих старых no-match карточек. Первичные ответы журналируются с SHA.
  Для применения подготовлены проверка exact identity/freshness/geometry,
  обычный GEO validator, row locks, preview/rollback trial и backup guard.
  Найденный feature сам по себе не считается применёнными координатами.
- Технический P1/P11 success подтверждает проверенные инварианты конкретного
  deployed SHA и карты, а не абсолютную достоверность всех внешних фактов.


## Дополнительные причины, подтверждённые при полном обходе

- ЛОТ-ОНЛАЙН v3: timeline соседнего рекомендованного product попадал в даты
  открытого лота. На трёх SHA-проверенных текущих страницах основной product
  имеет правильный кадастр и не имеет own даты; прежний глобальный селектор
  находил даты других product forms. В #1258 чтение ограничено точным main
  form и независимым hidden ID; версия detail повышена до 4. Это исправление
  подготовлено, но пока не внедрено. Исторические 6859 строк с датами требуют
  повторной проверки; само отсутствие публичной даты не доказывает ошибку.
- Map/native payload объединял процедуру, максимальную дату и фотографии
  разных публикаций общего canonical asset. Совпадение недвижимости не
  доказывает общие торги. Подготовлен exact-source выбор полей; публикации
  продолжают перечисляться отдельно, поля другой продажи не подставляются.
- Сохранённое naive business time — Europe/Moscow. Map выдавал его с Z,
  затем браузер прибавлял три часа. Подготовлена отдельная +03:00 сериализация;
  UTC время наблюдения цены сохраняет свою исходную семантику.
- Для неподтверждённых legacy дат LotOnline подготовлен явный field state:
  они сохраняются как история в базе, но не показываются подтверждёнными
  датами. Fresh scoped detail или проверенный primary receipt снимает эту
  неопределённость по конкретному полю, а не по всей карточке.
- Исторический wrong-object GEO может оставаться при неизменных source
  полях. Подготовлен explicit recheck, включённый в proof digest/preview и
  разрешённый только с fresh cadastral identity. Удаление лота не требуется.
- Verified source repair должен соблюдать durable user exclusions так же,
  как обычный импорт. Подготовлен общий отказ до записи; четыре существующих
  старых повторных импорта проверены и остаются archived.

Эти изменения находятся в #1258 и не считаются внедрёнными по состоянию
этого checkpoint. Массовое применение GIS, остальных source proofs, GEO,
публикация и exact-SHA acceptance остаются отдельными незавершёнными этапами.

- Дополнительный GEO read-path дефект: map detail и native query выбирали
  исторический snapshot после сброса current coordinates. Подготовлен общий
  current-projection guard: reset означает отсутствие текущей точки; другое
  текущее положение не получает прежнюю geometry/metadata. Исторические
  snapshots сохраняются, read path не пишет синтетический snapshot в базу.

# ЭТП — инкрементальные источники: реальные испытания и ограничения

Последняя проверка: 29.10.2026. Исходная диагностика: локальный снимок `TORGI_ETP_SMART_20261029_015909.zip` и обезличенный отчёт в `docs/etp-capture` старой Draft-ветки.

## Подтверждённые механизмы

- **МЭТС**: фильтр недвижимости `/search?q=eyJzZWFyY2hfY2F0ZWdvcnkiOiIzNiwzNCwzOSwzNywzOCwyOCw0MSJ9` и проверенная навигация `&page=2`. На двух сохранённых страницах присутствуют разные конкретные идентификаторы лотов. Каждая карточка должна подтверждать кадастровый номер, цену, статус и тип объекта.
- **ЦДТ**: официальный JSON каталог `/api/Trade/trades?Declare=true&RecieveReq=true&PageSize=20&PageNum=1` и `PageNum=2`. Должник (`name`) не является названием объекта. У каждой записи отдельные `tradeId` и `tradeLotId`; детали в `/trades/{tradeId}` обязательно сопоставляются с `tradeLotId`.
- **РТС-тендер**: браузерная проверка не завершена на автоматическом Chromium; увеличивать частоту HTTP-запросов или обходить CAPTCHA нельзя.

## Что можно тестировать в опубликованном API

Только из административной сессии:

- `GET /api/etp/pilots/m-ets.ru/batch-preview?limit=2`
- `GET /api/etp/pilots/cdtrf.ru/batch-preview?limit=2`
- Повторная страница: передайте `next_cursor` в параметре `cursor`.

Маршруты возвращают только идентификатор, название, категорию, кадастр, начальную/текущую цену и URL **подтверждённых карточек**, а также статистику отбраковки. `database_writes=0`, `archival_allowed=false`. Не считайте отсутствие карточки подтверждением отсутствия объекта на площадке.

## Подготовка записи в систему

`etp_incremental_source_specs()` создаёт две конфигурации для существующего `NationwideIngestionService`: максимум 2 страницы и 3 проверенные детальные ссылки на страницу, `reconcile_missing=False`. **Вызов не включён в `default_source_specs()` и в Celery.** Ни один из этих источников не может инициировать архивирование пропавших лотов.

Перед разрешением записи необходимы проверка живых карточек, полный выпуск green CI, свежая восстановленная резервная копия, проверки `SourceLot/ProcessedLot`, защита от ошибочных межисточниковых объединений, геокодирование и факт публикации точки на карте.

## Резервное копирование

До исправления ежедневная задача `phase3-lite-backup.yml` проваливалась при вызове Docker Desktop API, ещё до `pg_dump` (пример GitHub Actions run `40658542717`). Добавлен ограниченный безопасный запуск Docker через `scripts/ensure-docker-for-backup.ps1`, без остановки живых контейнеров и без автоматической очистки. Нельзя отмечать задачу #969 выполненной до **новой проверенной копии и изолированного восстановления**.

## Легенда индивидуальной готовности

- **S0 / BLOCKED:** достоверный контракт чтения каталога либо сетевого доступа не установлен.
- **S1 / CATALOGUE:** имеются ссылка/структура каталога и кандидаты; полное постраничное чтение и/или per-lot detail ещё не доказаны.
- **S2 / DETAIL_SAMPLE:** существуют примеры проверенной детальной карточки с полезными полями и регрессионными тестами. Это не обещание, что generic production importer действительно обогатит каждую запись.
- **S3 / SOURCE_ACCEPTED:** две сопоставимые полные read-only выборки, индивидуальный идентификатор, подтверждённая последняя страница, объяснённый drift, актуальные цены/статусы и независимая проверка карточек.
- **S4 / PRODUCTION_VERIFIED:** S3 плюс bounded import, сверка PostgreSQL, отсутствие чужого архивирования/склейки, GEO и фактически опубликованные метки проверены на конкретном production SHA.
- **BASELINE:** отдельный действующий production-коннектор; текущая S3/S4-приёмка НЕ следует автоматически из исторических DB-записей.

## Найденные технические риски кода — действия и приоритеты

### P1-A. Обход обязательного detail enrichment массовым импортом

- **Факты:** в etp_all_sources_campaign._connector специальным является только cdtrf.ru. Для прочих создаётся generic SOURCE_CONNECTOR_TYPES[source_id](). В ingestion._persist_page вызов enrich_lot выполняется **только** при наличии capability detail_enrichment; connector_type включает её лишь для etp-profit.ru и ausib.ru. В результате большинство generic-источников могут сохранять лишь catalogue-level записи и не проверять отдельную карточку, хотя метод fetch_lot существует.
- **Действие:** ввести source-specific проверку способности «individual detail verified», остановку записи неполной/неподтверждённой записи и явные тесты с fake connector для каждого источника. M-ETS направить через доказанный специализированный путь или доказать эквивалентность generic.
- **Критерий:** каждая записанная запись с ценой/статусом имеет воспроизводимый source detail proof, раздельный lot ID, версию enrichment и результат теста.

### P1-B. Неистинная операторская allowlist в production workflow

- **Факты:** workflow etp-all-new-sources-import-geo-map.yml без внешнего source acceptance перечисляет все 19 неблокированных профилей в ETP_ACCEPTED_SOURCE_IDS; _authorized() только проверяет наличие этих имён и флагов, **не** валидирует S3 acceptance evidence.
- **Действие:** не принимать эту переменную за свидетельство проверки. Формировать allowlist из независимо утверждённого реестра exact-SHA + source ID + evidence hash; по умолчанию 0 новых источников.
- **Критерий:** незаверенный источник нельзя записать даже при передаче всех env-флагов.

### P1-C. Побочные эффекты общего «non-reconciling» импорта

- **Факты:** SequentialCampaignService._run_active после цикла всегда вызывает reconcile_cross_source_duplicates(session) и _expire_elapsed_auctions(), хотя SourceSyncSpec.reconcile_missing=False. Это отдельные изменения состояния, не равные missing-lot archival, но опасные до полноценной source acceptance.
- **Действие:** до массового запуска сделать read-only preview всех side effects, ограничить scope только принятыми source/lot ID либо перенести последствия в отдельный подтверждаемый этап; проверить rollback и защиту существующей карты.
- **Критерий:** тесты доказывают нулевое архивирование/ошибочное объединение при неполном/провалившемся run.

### P1-D. «Последняя страница» может быть отсутствием найденного элемента интерфейса

- **Факты:** generic _has_next_page определяет продолжение по ссылке с page-параметром, onclick pagenum_send либо __doPostBack. Отсутствие совпадения ведёт к next_cursor=None и позволяет _sync_source вернуть success при require_source_end=True. Само наличие настроенного механизма страницы ещё не доказательство реального конца списка.
- **Действие:** для каждого ЭТП отдельная terminal-page proof с totalCount, API last-page или валидированной disabled-next/terminal state, полнота ID и два повторных read-only обхода. Запретить трактовать parser drift как пустой завершённый каталог.
- **Критерий:** конец источника доказан независимым условием, а не только отсутствием следующей ссылки.

### P1-E. Слабая изоляция GEO/map от ошибочной массовой кампании

- **Факты:** geocode_all выбирает записи из **всех 21 профилей**, а не только подтверждённые/импортированные этой кампанией. Workflow resume_after_import может пропустить стадию импорта и перейти к GEO/map без отдельной проверки идентичности и успешности предшествующего source-run в текущем invocation.
- **Действие:** связать GEO и публикацию с exact run_id, SHA, accepted source list и подтверждёнными external_id; для отсутствующего доказанного источника fail-closed. Старый MapDataset оставлять активным до финальной проверки.
- **Критерий:** QA проверяет реальные сохранённые lot_id → ProcessedLot → current coordinates → MapDataset → S3 → public WEB; при ошибке откат/отказ от активации.

### P1-F. Денежные поля и повторное обновление

- **Факты:** src/bankrotai/connectors/etp_sources/source_specific.py применяет цены через выражение «detail.start_price or lot.start_price» и аналогично current_price, многие парсеры и доменная модель оперируют float. Новая detail-карточка может содержать отсутствующее или сброшенное поле, которое нельзя путать с старым значением.
- **Действие:** единые Decimal RUB, различать «отсутствует/неизвестно/подтверждённый ноль» и происхождение значения; не переносить цену соседней процедуры или задаток. Сверить это с отложенным GitHub issue #1021.
- **Критерий:** тесты price-change/price-null/invalid-currency/lot-specific deposit и импорт с точной десятичной суммой.

### P2-G. Показатель прогресса и готовность источника

- **Факты:** progress() показывает 100% после завершения попыток, даже если среди источников failed; QA batch намеренно читает максимум две страницы и три кандидата и выставляет complete_source_inventory=False.
- **Действие:** разделить progress attempts / successful sources / source accepted / published map. Зелёный CI и QA двух страниц не превращать в готовую ЭТП.
- **Критерий:** операторский отчёт одновременно показывает attempted, succeeded, failed, accepted, imported, geo, published без фиктивного процента принятия.

### P2-H. Инфраструктура и воспроизводимость

- PR #1080 остаётся отдельно от main. Точный SHA 4ab3a77 на момент аудита имеет queued CI. Не объявлять merged/deployed.
- Исторический Home Phase 3 health [#41822362340](https://github.com/Maximiliamos/torgi/actions/runs/41822362340) 04.11 завершился ошибкой доступа к Docker Desktop Linux Engine. Это диагностика конкретного запуска, **не** свидетельство текущего состояния Docker.
- Доступ к российским ЭТП при включённом VPN ограничен; браузерные доказательства и API-контракты нужно сохранять в read-only режиме без VPN, без обхода защит, без публикации неочищенного HTML с личными данными.

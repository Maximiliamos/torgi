Локально успешно выполнен 161 Python-тест (2 PostgreSQL-only пропущены), Ruff,

Дополнительная live-проверка TBankrot для Ярославской области и категории «Вся

Фильтр теперь сохраняется как диагностический признак, но не скрывает карточки.
GEO `DetachedInstanceError` устранён копированием данных ORM внутри активной
SQLAlchemy-сессии и закреплён регрессионным тестом.

## Как работает программа

1. Коннекторы получают лоты ГИС «Торги», TBankrot, РАД/ЛОТ-ОНЛАЙН и ЕФРСБ,
   приводят ответы к `NormalizedLot` и сохраняют сырой источник и provenance.
2. `ProcessedLot` остаётся совместимым read model. `CanonicalLot` объединяет один
   физический объект, а `SourceLot` хранит отдельные публикации разных площадок.
3. Геокодирование создаёт версионированный `LotGeoSnapshot`; AI-запуски проходят
   Pydantic-валидацию и сохраняют provider/model/status. Неудача не подменяется
   вымышленными координатами или ценой.
4. Desktop запускает длительные операции через `QThread`; сервер — через
   FastAPI, Redis и Celery. React использует тот же доменный/API-слой.
5. Сделка включает процедуру, сценарии максимальной ставки, checklist участия,
   заметки, избранное и версии документов. Закрытые лоты архивируются, а не
   удаляются.

## Сильные стороны

- Консервативная модель данных: source-scoped identity, canonical/source split,
  история статусов и неизменяемые версии документов.
- Хорошая защита от ложной точности AI/GEO: строгие контракты, provenance,
  human-review и явные ошибки внешних сервисов.
- Зрелый production-каркас: Alembic, PostgreSQL/SQLite, Redis/Celery,
  непривилегированные контейнеры, healthchecks, rate limit и закрытые порты.
- Воспроизводимые lock-файлы и широкий CI: lint, typing, SQLite/PostgreSQL,
  migrations, web build и Docker/Playwright smoke.
- Финансовый калькулятор не использует AI-оценку как подтверждённую цену и
  требует консервативную цену продажи от пользователя.
- Резервные копии SQLite создаются консистентно через backup API и проверяются
  перед восстановлением.

## Слабые стороны и риски

### P0 — до публичной эксплуатации

1. **Нет полного серверного паритета длительных операций.** Celery массово
   синхронизирует только ГИС «Торги»; региональная задача не включает
   РАД/ЛОТ-ОНЛАЙН. Нет queue API для batch AI, batch GEO, повторного GEO и
   всероссийской трёхисточниковой синхронизации.
2. **RBAC заявлен, но не применён к действиям.** Любой вошедший пользователь может
   менять review status, participation, merge/split и сравнивать документы.
   Нужны разрешения `reader/analyst/admin` и tenant scope на каждом запросе.
3. **`API_READ_ONLY` вводит в заблуждение.** Режим пропускает curated POST/PUT
   (импорт, заметки, merge/split, checklist), то есть он не read-only. Это должно
   быть переименовано в `PUBLIC_API_CURATED_MODE`, а действительно неизменяемый
   режим — реализован отдельно.
4. **Критические монолиты.** `gui.py` — 6959 строк, `scrapers.py` — 3181,
   `api.py` — около 1140. Изменение одного источника или экрана имеет большую
   область регрессии.
5. **Нет production-приёмки внешних интеграций.** ЕФРСБ требует договор и
   credentials; TBankrot/ГИС/РАД/НСПД могут менять неофициальные или внешние
   контракты. Нужны canary contract tests и алерты.

### P1 — функциональная полнота и надёжность

6. Web пока не повторяет desktop-операции импорта HTML, Excel-экспорта, batch AI,
   batch GEO, кадастрового WMS и управления backup/restore. Backup/restore следует
   оставить административной операцией, а не переносить в обычный браузер.
7. Документный слой хранит версии и metadata diff, но не имеет download workers,
   object storage, антивирусной проверки и семантического сравнения текста.
8. Автоматическое объединение дублей опирается на ограниченный набор признаков;
   нет очереди human-review с показом evidence и undo-политикой.
9. Web-тесты слишком поверхностны для размера интерфейса: 5 unit-тестов и один
   smoke не проверяют расчёт, checklist, документы, карту, избранное и merge/split.
10. Нет SLO/метрик/трассировки, алертов по lag очереди, свежести источников,
    проценту GEO/AI ошибок и restore drill.
11. Нет корневой лицензии, release artifacts/SBOM и опубликованной политики
    совместимости схемы/API.

### P2 — качество продукта

12. React-клиент сосредоточен в одном `main.tsx`; русские подписи и технические
    имена полей смешаны с логикой. Нужны routes/features, design tokens и i18n.
13. Доступность не доказана: нет keyboard/focus/ARIA/contrast regression suite.
14. Нет полноценного цикла результата сделки: ставка → покупка → расходы → продажа
    → фактическая прибыль → backtesting/calibration.

## Паритет после текущего изменения

Web теперь покрывает поиск трёх источников, импорт найденного лота, реестр и
сохранённые фильтры, избранное, карточку и процедуру, переход из карточки в сделку,
калькулятор и историю сценариев, checklist, заметки, версии/сравнение документов,
manual merge/split, карту всей РФ с фильтрами цены/региона/архива, кадастровый
поиск, Яндекс.Карту с кластеризацией, desktop-маркерами и «светофором», review
status, health/quality/diagnostics и постановку региональной
синхронизации в deployment-режимах, где сервер явно объявляет эту capability.

Полным паритетом это можно назвать только после BAT-301…BAT-307 из roadmap:
браузер не должен имитировать desktop threads — длительные операции необходимо
перенести в надёжные серверные jobs с idempotency, progress и audit trail.

## Follow-up: desktop parity карты

После внешнего ревью карта дополнена точным двухрежимным desktop UX: исходная
левая панель содержит кадастровый поиск, управление границами/метками, поиск всей
РФ и фильтры; выбор маркера заменяет её карточкой с галереей, источниками,
кадастром, процедурой, сроками и «светофором». API карты теперь передаёт эти
данные одним пакетным запросом без N+1. Функция вынесена из React-монолита в
`features/map`, а серверная сборка payload — в `services/map_view.py`.

Замечание по iframe закрыто: Яндекс.Карты проверены в sandbox только с
`allow-scripts`. Родитель принимает сообщение лишь от ожидаемого `contentWindow`,
с opaque origin `null` и уникальным channel id. Входящие URL изображений и
исходящих кнопок ограничены протоколами HTTP(S).
